1. How ProxyChains Works Under the Hood

Unlike VPNs or network interfaces (like WireGuard or `tun/tap`), ProxyChains operates strictly in user space. It does not create a virtual network card or alter OS routing tables.

Instead, ProxyChains uses the dynamic linker trick: LD_PRELOAD=libproxychains4.so.

# When you execute:
proxychains4 nmap -sT -Pn -p 80,443 10.0.2.15

# What the OS actually does:
1. Dynamic linker preloads libproxychains4.so BEFORE standard libc.so.6.
2. Hooked C syscalls intercepted:
   - connect()
   - gethostbyname()
   - getaddrinfo()
   - close()
3. The real connect() to destination is cancelled.
4. Instead, a TCP connection is opened to the first proxy in the list.
5. SOCKS handshake is performed, commanding the proxy: "Tunnel me to the next hop".

2. The Three Chaining Modes

Mode Behavior Resilience Best Used For
dynamic_chain Traverses proxies in order. If a dead proxy is hit, it skips it and connects through the next alive proxy. High (Tolerates downed nodes) Standard penetration testing, pivoting through dynamic SSH tunnels.
strict_chain Traverses proxies in exact strict order. If a single proxy is dead, the entire connection fails immediately. Fragile (Strict order) High-security OPSEC where proxy sequence MUST follow exact geolocation hops.
random_chain Randomly selects a subset of proxies from the pool every time a connection is opened. Medium Evading rate limits, anti-scraping, and IDS correlation attacks.

3. The DNS Leak Danger (proxy_dns)

CRITICAL OPSEC WARNING: If proxy_dns is commented out or disabled in /etc/proxychains4.conf, your operating system will send DNS lookup requests for target hostnames directly to your local router's DNS server (UDP 53) in plaintext!

When proxy_dns is enabled:

  • ProxyChains intercepts getaddrinfo() and gethostbyname().
  • It returns a fake synthetic IP (e.g. 4.2.2.x) to the local application.
  • The actual domain name is encapsulated inside the SOCKS5 request payload and resolved remotely by the exit proxy!

4. Why SYN Scans (-sS) Fail in ProxyChains

NMAP RULE: Always use -sT -Pn with ProxyChains.

ProxyChains can only hook standard user-space POSIX socket functions (connect()). Tools like nmap -sS construct raw Layer-3 IP packets using AF_INET / SOCK_RAW, bypassing libc socket wrappers completely. Therefore, raw SYN scans bypass the proxy chain and leak your real IP address directly.

5. Real-World Lab Pivoting Scenario

# 1. Create a dynamic SOCKS5 proxy via SSH through your Kali or Windows host:
ssh -D 1080 -N -f general@192.168.0.149

# 2. Configure /etc/proxychains4.conf:
[ProxyList]
socks5  127.0.0.1 1080

# 3. Now run any tool directly into internal subnets:
proxychains4 curl http://192.168.0.117:9090
proxychains4 nmap -sT -Pn -p 22,80,445 192.168.0.155
